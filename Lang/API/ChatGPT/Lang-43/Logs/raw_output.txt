## 1. Behavior that differs

The defect is in how `appendQuotedString()` handles a quote encountered at the **current position when `escapingOn == true`**.

In the buggy version:

```java
if (escapingOn && c[start] == QUOTE) {
    return appendTo == null ? null : appendTo.append(QUOTE);
}
```

It appends the quote but **does not advance `ParsePosition`**.

The fixed version adds:

```java
next(pos);
```

before returning.

This matters because `applyPattern()` repeatedly calls `appendQuotedString()` while the parse position has not reached the end of the pattern. With a registry present, a quote can therefore leave the parser at exactly the same position forever in the buggy version. The JIRA issue identifies LANG-477 as an `ExtendedMessageFormat` problem involving an `OutOfMemory` condition with a custom format registry and a pattern containing single quotes. ([Apache Issues][1])

Defects4J's methodology also requires the buggy revision to fail and the fixed revision to pass for the supplied triggering behavior. ([GitHub][2])

---

## 2. Likely root cause visible from the source

The root cause is a **missing position increment**.

### BUGGY

```java
if (escapingOn && c[start] == QUOTE) {
    return appendTo == null ? null : appendTo.append(QUOTE);
}
```

The method returns while `pos` still points to the same quote.

### FIXED

```java
if (escapingOn && c[start] == QUOTE) {
    next(pos);
    return appendTo == null ? null : appendTo.append(QUOTE);
}
```

Now the parser moves beyond the quote.

Because `applyPattern()` calls:

```java
appendQuotedString(pattern, pos, stripCustom, true);
```

a pattern containing such a quote can repeatedly execute the same branch without making progress.

So the important invariant for the test is:

> **Whenever `appendQuotedString()` consumes a starting quote, the parse position must advance.**

---

## 3. Specific behavior the generated test should distinguish

The tests should verify that an `ExtendedMessageFormat` using a **non-null registry** can successfully process patterns containing single quotes.

The key distinction is:

| Situation                                | BUGGY                     | FIXED             |
| ---------------------------------------- | ------------------------- | ----------------- |
| Quote encountered with `escapingOn=true` | Position does not advance | Position advances |
| Construction/parsing of quoted pattern   | Can loop indefinitely     | Completes         |
| Pattern with quote at beginning          | Timeout/hang              | Completes         |
| Pattern with quote after normal text     | Timeout/hang              | Completes         |
| Empty quoted section                     | Timeout/hang              | Completes         |

The registry is important because `applyPattern()` immediately delegates to `MessageFormat` when `registry == null`, so the modified `appendQuotedString(..., true)` path is not exercised in that case.

---

## 4. Boundary cases, representative cases, and regression cases

I would use **four complementary tests**:

1. **Quote at the beginning of a quoted literal**

   * Directly targets the missing `next(pos)`.

2. **Quote after ordinary text**

   * Shows the problem is not restricted to a pattern beginning with a quote.

3. **Empty quoted section**

   * Tests the smallest possible quoted construct: two adjacent quotes.

4. **Ordinary pattern without quotes**

   * Regression/control case.
   * Confirms normal custom-registry parsing still works.

The first three use JUnit's timeout facility. This is appropriate because the buggy implementation's distinguishing behavior is non-termination rather than a normal incorrect return value.

The tests deliberately use an empty registry rather than copying any trigger-test registry or formatting data. The registry only needs to be non-null to enter the affected parsing path.

## 5. JUnit 4.12 test class

```java
package org.apache.commons.lang.text;

import java.util.HashMap;
import java.util.Map;

import org.junit.Test;

import static org.junit.Assert.assertEquals;

public class Lang43ExtendedMessageFormatTest {

    @Test(timeout = 2000)
    public void testQuotedLiteralAtBeginningMakesProgress() {
        Map registry = new HashMap();

        ExtendedMessageFormat format =
                new ExtendedMessageFormat("'hello'", registry);

        assertEquals("'hello'", format.toPattern());
    }

    @Test(timeout = 2000)
    public void testQuotedLiteralAfterOrdinaryTextMakesProgress() {
        Map registry = new HashMap();

        ExtendedMessageFormat format =
                new ExtendedMessageFormat("prefix 'hello' suffix", registry);

        assertEquals("prefix 'hello' suffix", format.toPattern());
    }

    @Test(timeout = 2000)
    public void testEmptyQuotedLiteralMakesProgress() {
        Map registry = new HashMap();

        ExtendedMessageFormat format =
                new ExtendedMessageFormat("before''after", registry);

        assertEquals("before''after", format.toPattern());
    }

    @Test(timeout = 2000)
    public void testPatternWithoutQuotesStillWorksWithRegistry() {
        Map registry = new HashMap();

        ExtendedMessageFormat format =
                new ExtendedMessageFormat("value {0}", registry);

        assertEquals("value {0}", format.toPattern());
    }
}
```

### Why these tests are independent

None of the tests directly call `appendQuotedString()`, use reflection, or reproduce the trigger test. They exercise the modified method through the normal public `ExtendedMessageFormat` constructor and `applyPattern()` path.

The quote patterns are derived from the source-level control-flow defect:

```java
if (escapingOn && c[start] == QUOTE)
```

rather than from the original trigger's exact input.

## 6. Defect detection strategy

### `testQuotedLiteralAtBeginningMakesProgress()`

**BUGGY VERSION:**
The constructor enters `applyPattern()`, reaches the quote at position `0`, calls `appendQuotedString(..., true)`, and returns without changing the position. The outer parsing loop encounters the same quote again indefinitely. The JUnit timeout causes the test to fail.

**FIXED VERSION:**
The quote is consumed because `next(pos)` advances the position. Parsing completes and the expected pattern is returned.

**Result:** defect-detecting.

---

### `testQuotedLiteralAfterOrdinaryTextMakesProgress()`

**BUGGY VERSION:**
The parser first consumes `"prefix "`. When it reaches the quote, the buggy `appendQuotedString()` leaves the position unchanged and the parsing loop does not make progress. The test times out.

**FIXED VERSION:**
The quote is consumed, the quoted text is parsed, and the constructor completes.

**Result:** defect-detecting.

---

### `testEmptyQuotedLiteralMakesProgress()`

**BUGGY VERSION:**
The first quote of the adjacent quote pair causes the same no-progress condition, so the test times out.

**FIXED VERSION:**
The first quote advances the position; the second quote is then processed normally. Construction completes.

**Result:** defect-detecting.

---

### `testPatternWithoutQuotesStillWorksWithRegistry()`

**BUGGY VERSION:**
No quote is encountered, so the defective branch is not reached. The pattern parses normally.

**FIXED VERSION:**
The pattern also parses normally.

**Result:** regression/control test, not defect-detecting.

### Expected suite result

| Test                                              | BUGGY              | FIXED |
| ------------------------------------------------- | ------------------ | ----- |
| `testQuotedLiteralAtBeginningMakesProgress`       | **FAIL — timeout** | PASS  |
| `testQuotedLiteralAfterOrdinaryTextMakesProgress` | **FAIL — timeout** | PASS  |
| `testEmptyQuotedLiteralMakesProgress`             | **FAIL — timeout** | PASS  |
| `testPatternWithoutQuotesStillWorksWithRegistry`  | PASS               | PASS  |

**Expected:** BUGGY = **3 failures / 1 pass**; FIXED = **0 failures / 4 passes**.

### Summary

* **Root cause:** `appendQuotedString()` returns immediately when it sees a starting quote with `escapingOn=true`, but the buggy code does not advance `ParsePosition`.
* **Targeted behavior:** quoted patterns must be consumed while making forward progress through `applyPattern()`.
* **Generated tests:** **4**
* **Defect-detecting tests:** **3**
* **Regression/control tests:** **1**
* **Independence:** the tests use different quote configurations derived from the source-level no-progress condition and access the behavior through the normal public API rather than copying the supplied trigger.

## Limitations

The main limitation is that the supplied source shows the control-flow difference but does not provide the exact runtime characteristics of the original trigger. Therefore, the tests detect the defect by asserting **termination within a timeout**, rather than asserting a normal returned value from the buggy implementation.

A timeout-based test can also be affected by an unusually slow test environment. The `2000 ms` limit is intentionally generous enough for this small constructor while still distinguishing the infinite/non-progressing buggy path. The issue itself is documented as an `OutOfMemory` problem associated with a custom registry and single quotes, which is consistent with the source-level infinite parsing behavior. ([Apache Issues][1])
