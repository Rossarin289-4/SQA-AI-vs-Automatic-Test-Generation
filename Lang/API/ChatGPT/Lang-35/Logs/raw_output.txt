## 1. พฤติกรรมที่แตกต่างกัน

Defect **Lang-35 / LANG-571** เกี่ยวกับ `ArrayUtils.add()` เมื่อ **ทั้ง array และ element เป็น `null`**

จาก commit ที่แก้ defect พบว่ามีการแก้ `add()` อยู่ 2 overload:

* `add(T[] array, T element)`
* `add(T[] array, int index, T element)`

ในเวอร์ชัน BUGGY เมื่อทั้งสอง argument เป็น `null` จะพยายามสร้าง `Object[]` แล้ว cast กลับเป็น `T[]` ซึ่งไม่ปลอดภัย และสามารถทำให้เกิด `ClassCastException` แทนที่จะรายงาน input ที่ไม่ถูกต้องอย่างชัดเจน

FIXED เปลี่ยนพฤติกรรมเป็น **throw `IllegalArgumentException` เมื่อ array และ element เป็น `null` พร้อมกัน** สำหรับทั้งสอง overload ([GitHub][1])

JIRA ของ Apache ก็ระบุ defect นี้ตรง ๆ ว่า `ArrayUtils.add(T[] array, T element)` สามารถสร้าง `ClassCastException` ที่ไม่ควรเกิดขึ้นได้ ([Apache Issues][2])

---

## 2. Likely root cause

### BUGGY

สำหรับ `add(T[] array, T element)` มี logic ประมาณนี้:

```java
Class<?> type = array != null
        ? array.getClass()
        : (element != null ? element.getClass() : Object.class);

T[] newArray = (T[]) copyArrayGrow1(array, type);
```

เมื่อ

```text
array   = null
element = null
```

จะเลือก:

```text
type = Object.class
```

แล้วสร้าง `Object[]`

จากนั้นจึง cast `Object[]` เป็น `T[]`

ปัญหาคือ generic array ที่ caller คาดหวังอาจเป็น เช่น `Integer[]` แต่ object จริงเป็น `Object[]` จึงสามารถเกิด `ClassCastException`

สำหรับ overload ที่มี `index` BUGGY ยังมีแนวทางที่ไม่ type-safe โดยสร้าง `Object[] { null }` แล้ว cast เป็น `T[]` เมื่อทั้งสองค่าเป็น `null` ([GitHub][1])

### FIXED

FIXED ตรวจสอบกรณีนี้โดยตรง:

```text
array == null
element == null
        ↓
IllegalArgumentException
```

ดังนั้น root cause หลักคือ **ไม่มีการจัดการกรณีที่ไม่สามารถระบุ component type ของ array ได้ เพราะทั้ง array และ element เป็น null**

## 3. Specific behavior ที่ test ต้องแยกให้ได้

Generated tests ควรตรวจว่า:

> เมื่อ `array == null` และ `element == null` การเรียก `ArrayUtils.add()` ต้องจบด้วย `IllegalArgumentException` ไม่ใช่ `ClassCastException`

และควรตรวจ **ทั้งสอง overload** เพราะ production code ถูกแก้ทั้งสองจุด:

| Test | Input pattern                            | BUGGY                | FIXED                      |
| ---- | ---------------------------------------- | -------------------- | -------------------------- |
| 1    | `add(null, null)`                        | `ClassCastException` | `IllegalArgumentException` |
| 2    | `add(null, index, null)`                 | `ClassCastException` | `IllegalArgumentException` |
| 3    | `add(null, nonNull)`                     | ทำงานปกติ            | ทำงานปกติ                  |
| 4    | `add(nonNull, null)`                     | ทำงานปกติ            | ทำงานปกติ                  |
| 5    | indexed + `null array`, non-null element | ทำงานปกติ            | ทำงานปกติ                  |
| 6    | indexed + non-null array, null element   | ทำงานปกติ            | ทำงานปกติ                  |

สอง test แรกเป็น **defect-detecting tests** โดยตรง ส่วน 4 test หลังเป็น regression tests เพื่อให้มั่นใจว่าการแก้กรณี `null/null` ไม่ทำให้ behavior ที่ถูกต้องของ `add()` กรณีอื่นเปลี่ยนไป

## 4. Boundary / representative / regression cases

### Boundary cases

**Case A — ทั้งสองค่าเป็น null**

```text
array = null
element = null
```

เป็น boundary สำคัญที่สุด เพราะไม่มีข้อมูลใดให้ method ใช้ระบุ component type

ทดสอบทั้ง:

```java
ArrayUtils.add(array, element)
```

และ

```java
ArrayUtils.add(array, index, element)
```

### Representative cases

**Case B — array เป็น null แต่ element มีค่า**

เช่น `Integer[]` กับ `Integer`

ควรสร้าง array ที่มี component type เป็น `Integer`.

**Case C — array มีค่า แต่ element เป็น null**

ควรสร้าง array ใหม่ที่ยังเป็น `Integer[]` และเติม `null` ต่อท้าย

### Regression cases

สำหรับ indexed overload ควรตรวจ behavior แบบเดียวกันด้วย เช่น

```text
null array + non-null element
non-null array + null element
```

จุดประสงค์คือไม่ใช่แค่ทำให้ BUGGY fail แต่ตรวจว่าการเพิ่ม `IllegalArgumentException` สำหรับ `null/null` ไม่ได้ทำลาย valid cases

## 5. Complete JUnit 4.12 test class

ชุดนี้ใช้ `Integer` แทน `String` เพื่อไม่ reproduce input จาก trigger test และออกแบบจาก source-level defect โดยตรง

```java
package org.apache.commons.lang3;

import static org.junit.Assert.assertArrayEquals;
import static org.junit.Assert.assertEquals;
import static org.junit.Assert.fail;

import org.junit.Test;

public class ArrayUtilsLang35Test {

    @Test
    public void testAddBothNullThrowsIllegalArgumentException() {
        Integer[] array = null;
        Integer element = null;

        try {
            ArrayUtils.add(array, element);
            fail("Expected IllegalArgumentException when array and element are both null");
        } catch (IllegalArgumentException expected) {
            // Expected behavior
        }
    }

    @Test
    public void testAddBothNullWithIndexThrowsIllegalArgumentException() {
        Integer[] array = null;
        Integer element = null;

        try {
            ArrayUtils.add(array, 0, element);
            fail("Expected IllegalArgumentException when array and element are both null");
        } catch (IllegalArgumentException expected) {
            // Expected behavior
        }
    }

    @Test
    public void testAddNullArrayWithNonNullElementCreatesCorrectType() {
        Integer[] array = null;
        Integer element = Integer.valueOf(42);

        Integer[] result = ArrayUtils.add(array, element);

        assertEquals(Integer[].class, result.getClass());
        assertArrayEquals(new Integer[] {42}, result);
    }

    @Test
    public void testAddNonNullArrayWithNullElementPreservesArrayType() {
        Integer[] array = new Integer[] {10, 20};
        Integer element = null;

        Integer[] result = ArrayUtils.add(array, element);

        assertEquals(Integer[].class, result.getClass());
        assertArrayEquals(new Integer[] {10, 20, null}, result);
    }

    @Test
    public void testIndexedAddNullArrayWithNonNullElementCreatesCorrectType() {
        Integer[] array = null;
        Integer element = Integer.valueOf(7);

        Integer[] result = ArrayUtils.add(array, 0, element);

        assertEquals(Integer[].class, result.getClass());
        assertArrayEquals(new Integer[] {7}, result);
    }

    @Test
    public void testIndexedAddNonNullArrayWithNullElementPreservesArrayType() {
        Integer[] array = new Integer[] {3, 6};
        Integer element = null;

        Integer[] result = ArrayUtils.add(array, 1, element);

        assertEquals(Integer[].class, result.getClass());
        assertArrayEquals(new Integer[] {3, null, 6}, result);
    }
}
```

## 6. Defect detection strategy + summary

### Test 1 — `testAddBothNullThrowsIllegalArgumentException`

**BUGGY**

```text
ArrayUtils.add(null, null)
        ↓
สร้าง Object[]
        ↓
cast เป็น Integer[]
        ↓
ClassCastException
```

ดังนั้น test **FAIL** เพราะไม่ได้รับ `IllegalArgumentException`

**FIXED**

```text
array == null
element == null
        ↓
IllegalArgumentException
```

ดังนั้น test **PASS**

**Defect-detecting: YES**

---

### Test 2 — `testAddBothNullWithIndexThrowsIllegalArgumentException`

**BUGGY**

กรณี `array == null` และ `element == null` ใน indexed overload ใช้ fallback ที่เป็น `Object[]` ซึ่งไม่ type-safe จึงสามารถเกิด `ClassCastException`

→ **FAIL**

**FIXED**

ตรวจพบว่า arguments ทั้งสองเป็น `null` และ throw `IllegalArgumentException`

→ **PASS**

**Defect-detecting: YES**

### สรุป

* **Root cause:** BUGGY ไม่จัดการกรณี `array == null && element == null` โดยตรง และพยายามสร้าง `Object[]` แล้ว cast เป็น generic array ซึ่งไม่ type-safe
* **Target behavior:** ทั้งสอง overload ต้อง throw `IllegalArgumentException` เมื่อ array และ element เป็น `null`
* **จำนวน tests:** **6 tests**
* **Defect-detecting tests:** **2 tests**
* **Regression tests:** **4 tests**
* **Expected result:** BUGGY **2 tests fail**, FIXED **all 6 tests pass**
* **ความเป็นอิสระจาก trigger:** ใช้ `Integer` และกรณีทดสอบที่ derive จาก source-level type problem โดยตรง ไม่ใช้ implementation หรือ exact input ของ `testLANG571`

Commit ที่แก้ LANG-571 ระบุชัดว่าการแก้ครอบคลุมทั้ง `add(T[] array, T element)` และ `add(T[] array, int index, T element)` และเปลี่ยนกรณีทั้งสอง argument เป็น `null` ให้เป็น `IllegalArgumentException` ([GitHub][1])

### Limitations

จาก source ที่ให้มา ส่วนของ `ArrayUtils` ถูกตัดออกบางช่วง จึงอาศัย diff ของ fixed revision เพื่อยืนยันรายละเอียดของ indexed overload อย่างไรก็ตาม commit `54c0f6b...` แสดง production changes ของทั้งสอง overload โดยตรง และแสดง test เดิมของโครงการด้วย ([GitHub][1])

ข้อจำกัดอีกอย่างคือชุดทดสอบนี้ตรวจ **observable API behavior** (`IllegalArgumentException` และชนิด/ค่าของ array) ไม่ได้ตรวจ internal implementation หรือ memory allocation ซึ่งสอดคล้องกับเป้าหมายของ defect-oriented testing.
