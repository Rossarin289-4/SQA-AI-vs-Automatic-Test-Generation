## 1. Behavior that differs

`LANG-432` concerns **locale-dependent case-insensitive matching** in `StringUtils.containsIgnoreCase`.

The intended behavior is that case-insensitive containment should not depend on the JVM's default locale. The JIRA description explicitly identifies the problem as using locale-sensitive `String.to*Case()` operations for case-insensitive comparisons. ([Apache Issues][1])

For example, under the Turkish locale, lowercase `i` and uppercase `I` have special casing rules. A case-insensitive search should still treat the corresponding upper/lowercase forms consistently.

The affected API is:

```java
StringUtils.containsIgnoreCase(String str, String searchStr)
```

The historical API documentation states that case-insensitivity is intended to follow the semantics of `String.equalsIgnoreCase(String)`, rather than locale-specific transformations. ([Javadoc][2])

---

## 2. Likely root cause visible from the source

The defect is caused by implementing case-insensitive matching through **locale-sensitive string case conversion**.

Conceptually, the buggy implementation behaves like:

```java
str.toUpperCase().indexOf(searchStr.toUpperCase()) >= 0
```

or an equivalent locale-sensitive `toLowerCase()` approach.

That is problematic because `String.toUpperCase()` without an explicit locale uses the JVM default locale.

For Turkish, for example:

```text
"i".toUpperCase(Turkish)  -> "İ"
"I".toUpperCase(Turkish)  -> "I"
```

Therefore a string containing `"I"` can fail to match a search string containing `"i"` even though the operation is supposed to ignore case.

The corrected implementation uses character-region comparison rather than converting the complete strings according to the default locale. Historical Commons Lang implementations use `regionMatches(true, ...)` for this purpose.

## 4. Complete JUnit 4.12 test class

```java
package org.apache.commons.lang;

import static org.junit.Assert.assertFalse;
import static org.junit.Assert.assertTrue;

import java.util.Locale;

import org.junit.Test;

public class StringUtilsLang40Test {

    @Test
    public void testContainsIgnoreCaseIsNotAffectedByTurkishLocale() {
        Locale original = Locale.getDefault();

        try {
            Locale.setDefault(new Locale("tr", "TR"));

            assertTrue(
                StringUtils.containsIgnoreCase("DIGITAL", "digital")
            );
        } finally {
            Locale.setDefault(original);
        }
    }

    @Test
    public void testContainsIgnoreCaseWithMixedTextUnderTurkishLocale() {
        Locale original = Locale.getDefault();

        try {
            Locale.setDefault(new Locale("tr", "TR"));

            assertTrue(
                StringUtils.containsIgnoreCase(
                    "The SILVER Device",
                    "silver"
                )
            );
        } finally {
            Locale.setDefault(original);
        }
    }

    @Test
    public void testContainsIgnoreCaseWithUppercaseTextAndLowercaseSearch() {
        Locale original = Locale.getDefault();

        try {
            Locale.setDefault(new Locale("tr", "TR"));

            assertTrue(
                StringUtils.containsIgnoreCase(
                    "MINIMUM VALUE",
                    "minimum"
                )
            );
        } finally {
            Locale.setDefault(original);
        }
    }

    @Test
    public void testContainsIgnoreCaseDoesNotMatchDifferentLetters() {
        Locale original = Locale.getDefault();

        try {
            Locale.setDefault(new Locale("tr", "TR"));

            assertFalse(
                StringUtils.containsIgnoreCase(
                    "DIGITAL",
                    "digitalx"
                )
            );
        } finally {
            Locale.setDefault(original);
        }
    }

    @Test
    public void testContainsIgnoreCaseNormalCaseInsensitiveMatch() {
        Locale original = Locale.getDefault();

        try {
            Locale.setDefault(new Locale("tr", "TR"));

            assertTrue(
                StringUtils.containsIgnoreCase(
                    "Computer Science",
                    "SCIENCE"
                )
            );
        } finally {
            Locale.setDefault(original);
        }
    }
}
```

## 6. Summary and limitations

### Summary

* **Root cause:** `containsIgnoreCase` used locale-sensitive case conversion for a comparison that should be locale-independent.
* **Targeted behavior:** case-insensitive substring matching involving `I/i` while the default locale is Turkish.
* **Number of generated tests:** **5**
* **Primary defect-detecting tests:** **3**
* **Regression/boundary tests:** **2**
* The tests directly call `StringUtils.containsIgnoreCase`.
* No reflection is used.
* No production code is modified.
* The supplied trigger test is not invoked.
* The test inputs are independently selected rather than copied from the trigger.

The historical Commons Lang API defines `containsIgnoreCase` as case-insensitive containment, and the later implementation uses region-based case-insensitive matching rather than locale-dependent whole-string conversion. ([Javadoc][2])

Because of that, the expected BUGGY failures above are based on the documented LANG-432 defect rather than a direct execution of the two supplied workspaces.
