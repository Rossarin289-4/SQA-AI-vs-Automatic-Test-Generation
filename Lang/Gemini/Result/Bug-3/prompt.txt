3. AVAILABLE DEFECT INFORMATION
============================================================

The defect is located in:

org.apache.commons.lang3.math.NumberUtils.createNumber(String)

The buggy implementation attempts to create a Float first and then
a Double for decimal/exponent input without using the number of
digits after the decimal point to restrict the selected numeric type.

The buggy implementation contains logic equivalent to:

    final Float f = createFloat(str);

followed by:

    final Double d = createDouble(str);

before falling back to BigDecimal.

The value:

    numDecimals = dec.length()

is calculated but is not used to restrict the Float/Double branches.

The fixed implementation introduces the following restrictions:

    if (numDecimals <= 7) {
        createFloat(...)
    }

and:

    if (numDecimals <= 16) {
        createDouble(...)
    }

Therefore:

- values with 7 or fewer decimal digits may be represented as Float
- values with 8 through 16 decimal digits should be represented as Double
- values with more than 16 decimal digits should fall through to BigDecimal

The core defect concerns precision loss caused by selecting Float
for decimal values that require higher precision.
