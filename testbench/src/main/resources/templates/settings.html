02

Algorithms สำหรับเปรียบเทียบ

เลือก algorithm ได้หนึ่งรายการหรือหลายรายการ ระบบจะรันทุกรายการที่เลือกแยกกัน

แต่ละ algorithm สร้าง test suite แยกกัน ใช้กับ Project/Bug ที่ระบุใน run และใช้ budget เดียวกันเพื่อเปรียบเทียบ · เพิ่มตัวเลือกใหม่ได้เมื่อมีการพัฒนา algorithm ในระบบ

03

Master Prompt สำหรับ Defects4J

แก้รูปแบบงานและรายงานสำหรับ run ใหม่ โดยระบบเติมข้อมูลของแต่ละ bug ให้

แก้ได้: คำสั่งและรูปแบบคำตอบ · ห้ามเปลี่ยนชื่อ placeholder

ต้องมี: {{PROJECT_ID}} = Project ID · {{BUG_ID}} = Bug ID · ช่อง source หนึ่งช่อง: {{SOURCE_CODE}} = source รุ่น fixed (ใช้คู่กับ oracle fixed ของ algorithm · v13 ขึ้นไป) หรือ {{BUGGY_SOURCE}} = source รุ่น buggy (v1–v12)

ใช้เพิ่มได้: {{TARGET_CLASS}} · {{TARGET_METHOD}} · {{BUG_REPORT_ID}} ระบบเติมจากข้อมูลเป้าหมายที่มี; ถ้าไม่ทราบจะแทนด้วย NOT_SPECIFIED ไม่เดาค่าเอง

Skill ของระบบเก็บกติกาคงที่ ส่วน Master Prompt นี้กำหนดโจทย์และรูปแบบผลลัพธ์สำหรับ run ใหม่

แก้ได้: คำสั่งวิเคราะห์ วิธีออกแบบ test และรูปแบบรายงาน · ห้ามลบหรือเปลี่ยนชื่อ placeholder บังคับ ระบบเติมข้อมูลจริงให้เอง

ส่ง prompt เดียวกันให้ AI ทุกรายการที่เลือก และเก็บ prompt ที่ใช้จริงไว้กับ run; เปลี่ยน prompt มีผลกับ run ใหม่เท่านั้น

ผลของแต่ละเวอร์ชันนับแยกกัน (เปลี่ยนเวอร์ชันแล้ว bug ที่ทำไปแล้วจะรันใหม่ได้สำหรับ AI) · algorithm ไม่ใช้ prompt จึงไม่รันซ้ำ · ถ้าแก้ข้อความด้านล่างเองจะนับเป็น custom

Placeholder บังคับสามตัวต้องคงอยู่; ตัวเลือกอีกสามตัวใช้ได้เมื่ออยากให้ AI เห็น class, method และ report ID ของ bug ที่มีข้อมูล
