### Identify

1. **The behavior that differs:** 
   The difference between the buggy and fixed implementations of `StringUtils.indexOfAny` (and related methods affected by character handling in `indexOfAny`) lies in how supplementary characters (Unicode surrogate pairs, such as characters outside the Basic Multilingual Plane spanning two `char` units, i.e., code points $> 0xFFFF$) are handled during character index searches. In the buggy version, high/low surrogate characters or strings containing supplementary code points are mishandled, leading to incorrect index lookup results or failure to correctly match code points/char arrays with supplementary characters.

2. **The likely root cause visible from the source:** 
   The root cause stems from incorrect handling of `Character.isSupplementaryCodePoint` / surrogate pairs in methods scanning characters or char sequences (specifically inside `indexOfAny`), where 16-bit `char` primitives are checked or iterated independently rather than properly accounting for 32-bit Unicode code points via `Character.codePointAt` or handling high/low surrogate pairs.

3. **The specific behavior that a generated test should distinguish:** 
   A test should check searching for and locating characters/strings containing supplementary Unicode characters (surrogate pairs) using `StringUtils.indexOfAny`. The buggy version fails to return the correct index or misses matching supplementary characters properly, whereas the fixed version correctly handles surrogate pairs and returns the expected index.

4. **Boundary cases, representative cases, and regression cases that are independently designed:**
   - Searching a string containing a supplementary character with a search string/array containing that same supplementary character.
   - Searching with malformed surrogate sequences or boundary surrogate values.
   - Searching strings where supplementary characters appear before or after standard BMP characters.
