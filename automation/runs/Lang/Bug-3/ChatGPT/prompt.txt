2. BUG INFORMATION
============================================================

The defect concerns floating-point parsing in NumberUtils.createNumber(String).

The buggy implementation attempts to parse a decimal/exponent number as Float before trying Double and BigDecimal.

The relevant buggy source contains:

    int numDecimals = 0;

When a decimal point is present:

    numDecimals = dec.length();

The variable numDecimals is calculated with the stated purpose of checking the required precision, but the value is not subsequently used to control the floating-point type-selection logic.

For a number without an explicit floating-point type suffix, the buggy implementation eventually executes logic equivalent to:

    final Float f = createFloat(str);
    if (!(f.isInfinite() || (f.floatValue() == 0.0F && !allZeros))) {
        return f;
    }

followed by:

    final Double d = createDouble(str);
    if (!(d.isInfinite() || (d.doubleValue() == 0.0D && !allZeros))) {
        return d;
    }

and finally:

    return createBigDecimal(str);

Therefore, a value that can be represented as a finite non-zero Float may be returned as Float even when Float cannot preserve the decimal precision represented by the input.

The defect should be tested through observable behavior of createNumber(String), especially:

- returned numeric type
- preservation of decimal precision
- difference between Float and Double representation
- decimal values requiring more precision than a Float can safely preserve
