## 1. SOURCE CODE ANALYSIS

The defect is in `LookupTranslator`'s use of `CharSequence` objects as `HashMap` keys. In the buggy version, the constructor stores the original lookup key directly:

```java
HashMap<CharSequence, CharSequence>
```

and `translate()` performs:

```java
lookupMap.get(subSeq)
```

where `subSeq` comes from `input.subSequence(...)`. 

The important problem is that two different `CharSequence` implementations can contain the **same characters** but have different `equals()`/`hashCode()` behavior. Therefore, a lookup such as `"abc"` can fail even though the input subsequence also represents `"abc"`.

The fixed version normalizes both sides to `String`:

```java
lookupMap.put(seq[0].toString(), seq[1]);
lookupMap.get(subSeq.toString());
```

so lookup depends on the textual characters rather than the concrete `CharSequence` implementation. 

The tests therefore use custom `CharSequence` implementations whose equality is deliberately implementation-sensitive. This directly exercises the interoperability problem described in the defect information.

## 2. TEST CASE DESIGN

The following tests use several variations rather than repeating one identical scenario.

| Test | Lookup key                            | Input                              | Main variation             | Expected                 |
| ---- | ------------------------------------- | ---------------------------------- | -------------------------- | ------------------------ |
| 1    | Custom `KeySequence`                  | Custom `InputSequence`             | Different implementations  | Translate whole sequence |
| 2    | `String`                              | Custom `InputSequence`             | String → custom input      | Translate whole sequence |
| 3    | Custom `KeySequence`                  | `String`                           | Custom key → String input  | Translate whole sequence |
| 4    | Custom `KeySequence` `"abc"` + `"ab"` | Custom `InputSequence` `"abcX"`    | Greedy longest-match       | `"abc"` consumed first   |
| 5    | `String`                              | Custom `InputSequence` with prefix | Matching at non-zero index | Translate substring only |

The helper classes intentionally have **class-sensitive equality**. Thus, for example, a `KeySequence("abc")` and an `InputSequence("abc")` represent identical characters but are not equal as objects.

This creates exactly the situation described in the source analysis: the buggy implementation may fail its `HashMap` lookup, while the fixed implementation converts both representations to `String`.

## 3. JUNIT 4.12 TEST CODE

The following is one complete test class suitable for saving as `LookupTranslatorTest.java`. It directly exercises `LookupTranslator`, does not invoke the original `testLang882`, and does not use the original trigger input values.

```java
package org.apache.commons.lang3.text.translate;

import static org.junit.Assert.assertEquals;

import java.io.IOException;
import java.io.StringWriter;
import java.io.Writer;

import org.junit.Test;

public class LookupTranslatorTest {

    /**
     * CharSequence used for lookup keys.
     *
     * Equality is intentionally restricted to the same implementation
     * so that it behaves differently from String-based equality.
     */
    private static final class KeySequence implements CharSequence {

        private final String value;

        KeySequence(String value) {
            this.value = value;
        }

        @Override
        public int length() {
            return value.length();
        }

        @Override
        public char charAt(int index) {
            return value.charAt(index);
        }

        @Override
        public CharSequence subSequence(int start, int end) {
            return new KeySequence(value.substring(start, end));
        }

        @Override
        public String toString() {
            return value;
        }

        @Override
        public boolean equals(Object obj) {
            if (!(obj instanceof KeySequence)) {
                return false;
            }
            return value.equals(((KeySequence) obj).value);
        }

        @Override
        public int hashCode() {
            return value.hashCode();
        }
    }

    /**
     * Different CharSequence implementation used for translator input.
     *
     * Its equality is intentionally restricted to InputSequence objects.
     */
    private static final class InputSequence implements CharSequence {

        private final String value;

        InputSequence(String value) {
            this.value = value;
        }

        @Override
        public int length() {
            return value.length();
        }

        @Override
        public char charAt(int index) {
            return value.charAt(index);
        }

        @Override
        public CharSequence subSequence(int start, int end) {
            return new InputSequence(value.substring(start, end));
        }

        @Override
        public String toString() {
            return value;
        }

        @Override
        public boolean equals(Object obj) {
            if (!(obj instanceof InputSequence)) {
                return false;
            }
            return value.equals(((InputSequence) obj).value);
        }

        @Override
        public int hashCode() {
            return value.hashCode();
        }
    }

    @Test
    public void testDifferentCustomCharSequenceImplementations() throws IOException {
        LookupTranslator translator = new LookupTranslator(
                new CharSequence[] {
                        new KeySequence("alpha"),
                        "A"
                });

        Writer out = new StringWriter();

        int consumed = translator.translate(
                new InputSequence("alpha"),
                0,
                out);

        assertEquals("A", out.toString());
        assertEquals(5, consumed);
    }

    @Test
    public void testStringLookupKeyWithCustomInputSequence() throws IOException {
        LookupTranslator translator = new LookupTranslator(
                new CharSequence[] {
                        "beta",
                        "B"
                });

        Writer out = new StringWriter();

        int consumed = translator.translate(
                new InputSequence("beta"),
                0,
                out);

        assertEquals("B", out.toString());
        assertEquals(4, consumed);
    }

    @Test
    public void testCustomLookupKeyWithStringInput() throws IOException {
        LookupTranslator translator = new LookupTranslator(
                new CharSequence[] {
                        new KeySequence("gamma"),
                        "G"
                });

        Writer out = new StringWriter();

        int consumed = translator.translate(
                "gamma",
                0,
                out);

        assertEquals("G", out.toString());
        assertEquals(5, consumed);
    }

    @Test
    public void testGreedyMatchingWithDifferentCharSequenceImplementation() throws IOException {
        LookupTranslator translator = new LookupTranslator(
                new CharSequence[] {
                        new KeySequence("abc"),
                        "LONG"
                },
                new CharSequence[] {
                        new KeySequence("ab"),
                        "SHORT"
                });

        Writer out = new StringWriter();

        int consumed = translator.translate(
                new InputSequence("abcX"),
                0,
                out);

        assertEquals("LONG", out.toString());
        assertEquals(3, consumed);
    }

    @Test
    public void testDifferentCharSequenceAtNonZeroIndex() throws IOException {
        LookupTranslator translator = new LookupTranslator(
                new CharSequence[] {
                        "delta",
                        "D"
                });

        Writer out = new StringWriter();

        int consumed = translator.translate(
                new InputSequence("xxdelta"),
                2,
                out);

        assertEquals("D", out.toString());
        assertEquals(5, consumed);
    }
}
```

## 4. DEFECT DETECTION STRATEGY

### Test 1 — Different custom implementations

**Representations**

* Lookup key: `KeySequence("alpha")`
* Input: `InputSequence("alpha")`
* Both contain exactly `"alpha"`.
* They are different `CharSequence` implementations.

**Buggy behavior**

The buggy implementation stores the `KeySequence` object and later calls `lookupMap.get()` using the `InputSequence` returned by `subSequence()`. Because their `equals()` methods only accept their own implementation type, the lookup does not match.

**Fixed behavior**

The fixed implementation converts the lookup key and input subsequence to `String`, so both become `"alpha"`.

**Expected**

```text
Output = A
Consumed = 5
```

This is the most direct test of the defect mechanism.

---

### Test 2 — String lookup key and custom input

**Representations**

* Lookup key: `String("beta")`
* Input: `InputSequence("beta")`

The buggy version performs a lookup using `InputSequence` against a `String` key.

The fixed version converts the input subsequence to `String`, producing `"beta"`.

**Expected**

```text
Output = B
Consumed = 4
```

This reverses the representation relationship from Test 1 and checks the other direction of interoperability.

---

### Test 3 — Custom lookup key and String input

**Representations**

* Lookup key: `KeySequence("gamma")`
* Input: ordinary `String("gamma")`

The buggy implementation stores the custom object but receives a `String` from `String.subSequence()`.

The fixed implementation normalizes both to `"gamma"`.

**Expected**

```text
Output = G
Consumed = 5
```

This checks the opposite direction from Test 2.

---

### Test 4 — Different implementations with greedy matching

The translator contains two entries:

```text
"abc" -> "LONG"
"ab"  -> "SHORT"
```

The input is:

```text
"abcX"
```

The method should try the longest possible matching sequence first and consume `"abc"`.

The test therefore checks both:

```text
Output = LONG
Consumed = 3
```

The test is useful because the defect can prevent **both** candidate keys from being found when the input's `CharSequence` implementation differs from the lookup-key implementation. The fixed normalization should still find the longest textual match. The source explicitly identifies multiple lookup entries and greedy matching as a meaningful test dimension. 

---

### Test 5 — Match at a non-zero index

Input:

```text
"xxdelta"
```

Translation begins at index `2`.

The expected result is:

```text
Output = D
Consumed = 5
```

This checks that the interoperability issue also occurs when the relevant `CharSequence` is obtained from a non-zero position rather than starting at the beginning of the input.

---

## 5. SUMMARY

The test suite focuses specifically on the difference between:

```java
lookupMap.get(subSeq)
```

in Lang-4b and:

```java
lookupMap.get(subSeq.toString())
```

in Lang-4f. 

The key idea is to make the lookup key and input represent the **same textual characters** while deliberately using different `CharSequence` implementations.

For a test to actually count as detecting Lang-4, the later experiment must demonstrate:

```text
BUGGY VERSION → FAIL
FIXED VERSION → PASS
```

The source-level analysis strongly motivates these tests, but actual detection cannot be claimed until the class is executed against both Lang-4b and Lang-4f. This follows the experiment's specified detection criterion. 

---

## 6. LIMITATIONS

1. **No execution result is claimed.** The test suite has been designed from the supplied source-level defect information; it has not been executed against Lang-4b and Lang-4f here.

2. **Custom `CharSequence` behavior is intentionally artificial.** The helper classes are designed to expose the exact equality/hash-code interoperability problem rather than represent a particular production application's `CharSequence`.

3. **Actual detection depends on the Defects4J environment.** The final BUGGY-FAIL/FIXED-PASS classification must be established by running the generated test against both specified versions.

4. The tests intentionally avoid the original `LookupTranslatorTest::testLang882` and the exact original trigger inputs, as required by the experiment.
