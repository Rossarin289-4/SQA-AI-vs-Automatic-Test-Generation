## 1. SOURCE CODE ANALYSIS

จุดที่ defect อยู่ใน `CharSequenceTranslator.translate(CharSequence input, Writer out)` โดยเฉพาะ loop ที่เลื่อน `pos` หลังจาก translator บอกว่ากิน input ไป `consumed` ตัว. จาก source ที่ให้มา มีการเปลี่ยนเพียงจุดเดียว:

```java
for (int pt = 0; pt < consumed; pt++) {
    pos += Character.charCount(Character.codePointAt(input, pos));
}
```

เปลี่ยนเป็น:

```java
for (int pt = 0; pt < consumed; pt++) {
    pos += Character.charCount(Character.codePointAt(input, pt));
}
```

JIRA ของ LANG-857 ระบุว่า defect เกี่ยวข้องกับการจัดการ **surrogate pair** และ BUGGY version สามารถเกิด `StringIndexOutOfBoundsException` ระหว่าง `Character.codePointAt()` ได้ ([Apache Issues][1])

### 1.1 Behavior ที่แตกต่าง

ใน BUGGY version `pos` ถูกใช้เป็น index ของ `codePointAt()` ทุกครั้งใน loop

```java
Character.codePointAt(input, pos)
```

ปัญหาคือ `pos` ถูกเพิ่มขึ้นภายใน loop ด้วย

สมมติ translator รายงานว่า consumed = `2` สำหรับ surrogate pair:

```text
เริ่ม pos = 0

รอบแรก:
codePointAt(input, 0)
→ surrogate pair
→ charCount = 2
→ pos = 2

รอบที่สอง:
codePointAt(input, 2)
→ index อาจอยู่นอก input
→ StringIndexOutOfBoundsException
```

นี่สอดคล้องกับ stack trace ของ LANG-857 ซึ่งแสดง exception จาก `Character.codePointAt()` ที่ถูกเรียกจาก `CharSequenceTranslator.translate()` ([Apache Issues][1])

### 1.2 Likely root cause

Root cause คือ **ใช้ `pos` ซึ่งเป็น cursor ที่เปลี่ยนระหว่าง loop เป็น argument ของ `codePointAt()`**

ขณะที่ fixed implementation ใช้ `pt` เป็น index ของแต่ละรอบ:

```java
Character.codePointAt(input, pt)
```

การเปลี่ยนแปลงนี้ตรงกับ developer patch ของ Lang-6 ที่เผยแพร่ในงานวิจัยเกี่ยวกับ Defects4J ด้วย ([GitHub][2])

### 1.3 Behavior ที่ test ควรแยก

เราต้องสร้างสถานการณ์ที่:

* translator consume surrogate pair
* `consumed` มากกว่า 1
* loop ต้องทำงานมากกว่า 1 รอบ
* BUGGY version จะเรียก `codePointAt()` ด้วย `pos` ที่ถูกเลื่อนไปแล้ว
* FIXED version จะไม่เกิด exception

เพื่อไม่ใช้ trigger test เดิม เราจะใช้ **surrogate pair คนละตัว** และใช้ `LookupTranslator` เพื่อสร้าง translation ที่ consume surrogate-pair input

## 2. TEST CASE DESIGN

เลือก **2 tests** ที่ครอบคลุมตำแหน่งของ surrogate pair ต่างกัน

### Test 1 — Surrogate pair อยู่ต้น input

Input:

```text
🙂
```

โดยใช้ Unicode code point `U+1F642`

และสร้าง `LookupTranslator` ให้แปลง:

```text
🙂 → X
```

เหตุผลที่ใช้ `LookupTranslator` คือมันเป็น `CharSequenceTranslator` จริงของ Apache Commons Lang และมี API สำหรับ lookup translation โดยตรง ([Apache Commons][3])

Expected:

```text
X
```

---

### Test 2 — มี normal character ก่อน surrogate pair

Input:

```text
A🙂
```

mapping:

```text
🙂 → X
```

Expected:

```text
AX
```

test นี้เพิ่มกรณีที่ surrogate pair ไม่ได้อยู่ที่ index `0` เพื่อดูว่า implementation จัดการ `pos` ที่ไม่ใช่จุดเริ่มต้นได้หรือไม่

สอง test ไม่ใช่ duplicate กันทั้งหมด เพราะ test แรกตรวจ boundary ที่ translator เริ่มต้นที่ index 0 ส่วน test ที่สองตรวจการจัดการ cursor หลังมี character ก่อนหน้า

## 3. JUNIT 4.12 TEST CODE

```java
package org.apache.commons.lang3.text.translate;

import static org.junit.Assert.assertEquals;

import org.junit.Test;

public class CharSequenceTranslatorTest {

    @Test
    public void testTranslateSupplementaryCharacterAtBeginning() {
        CharSequenceTranslator translator =
                new LookupTranslator(
                        new CharSequence[][] {
                                { "\uD83D\uDE42", "X" }
                        });

        assertEquals("X", translator.translate("\uD83D\uDE42"));
    }

    @Test
    public void testTranslateSupplementaryCharacterAfterRegularCharacter() {
        CharSequenceTranslator translator =
                new LookupTranslator(
                        new CharSequence[][] {
                                { "\uD83D\uDE42", "X" }
                        });

        assertEquals("AX", translator.translate("A\uD83D\uDE42"));
    }
}
```

## 4. DEFECT DETECTION STRATEGY

### Test 1: `testTranslateSupplementaryCharacterAtBeginning`

Input:

```java
"\uD83D\uDE42"
```

เป็น surrogate pair ของ code point `U+1F642`.

`LookupTranslator` จับคู่ surrogate pair นี้กับ `"X"` และรายงานจำนวนที่ consume กลับไปให้ `CharSequenceTranslator`.

### BUGGY VERSION

เมื่อ `consumed` ทำให้ loop ทำงานมากกว่า 1 รอบ:

```java
for (int pt = 0; pt < consumed; pt++) {
    pos += Character.charCount(
        Character.codePointAt(input, pos)
    );
}
```

`pos` ถูกเลื่อนไปจนถึงท้าย input หลังรอบแรก แล้วรอบถัดไปพยายามอ่านด้วย index ที่ไม่ถูกต้อง

จึงคาดว่าจะเกิด:

```text
StringIndexOutOfBoundsException
```

ดังนั้น:

**BUGGY → FAIL**

### FIXED VERSION

Fixed implementation ใช้:

```java
Character.codePointAt(input, pt)
```

แทน `pos` ตาม developer patch. ([GitHub][2])

จึงไม่เรียก `codePointAt()` ด้วย cursor ที่ถูกเลื่อนไปจนเกินขอบเขต

Expected output:

```text
X
```

ดังนั้น:

**FIXED → PASS**

---

### Test 2: `testTranslateSupplementaryCharacterAfterRegularCharacter`

Input:

```java
"A\uD83D\uDE42"
```

Expected:

```text
AX
```

### BUGGY VERSION

เมื่อถึง surrogate pair ที่ index 1, `pos` จะชี้ไปยัง surrogate pair ก่อนที่จะถูกเพิ่มตาม `charCount()`.

หลังจากรอบแรก `pos` จะถูกเลื่อนไปจนถึงท้าย input แล้วรอบถัดไปของ loop จะใช้:

```java
Character.codePointAt(input, pos)
```

ซึ่งอาจอ่านนอกขอบเขต

Expected:

**BUGGY → FAIL**

โดย failure ที่คาดหวังคือ `StringIndexOutOfBoundsException` เช่นเดียวกับ defect mechanism ที่รายงานใน LANG-857. ([Apache Issues][1])

### FIXED VERSION

ใช้ `pt` เป็นตำแหน่งที่อ่าน code point แทน `pos`:

```java
Character.codePointAt(input, pt)
```

จึงหลีกเลี่ยงการอ่านจาก cursor ที่ถูกเลื่อนไปแล้ว

Expected:

```text
AX
```

ดังนั้น:

**FIXED → PASS**

### Expected result

| Test                        | BUGGY                                    | FIXED |
| --------------------------- | ---------------------------------------- | ----- |
| Surrogate pair at beginning | FAIL / `StringIndexOutOfBoundsException` | PASS  |
| Surrogate pair after `A`    | FAIL / `StringIndexOutOfBoundsException` | PASS  |

ดังนั้นถ้า execution จริงให้ผลตามนี้ ทั้งสอง test จะเข้าเกณฑ์ **defect-detecting test** คือ BUGGY fail และ FIXED pass

## 5. SUMMARY

* **Root cause:** BUGGY implementation ใช้ `pos` ที่เปลี่ยนค่าไปเรื่อย ๆ เป็น argument ของ `Character.codePointAt()` ภายใน loop
* **Defect:** การประมวลผล translator ที่ consume surrogate-pair input สามารถทำให้ `pos` ไปถึงท้าย input แล้วถูกนำไปใช้เป็น index อีกครั้ง จนเกิด `StringIndexOutOfBoundsException`
* **Fix:** เปลี่ยนจาก `codePointAt(input, pos)` เป็น `codePointAt(input, pt)` ตาม developer patch ของ Lang-6 ([GitHub][2])
* **Generated tests:** 2 tests

  1. surrogate pair อยู่ต้น input
  2. surrogate pair อยู่หลัง regular character
* ใช้ surrogate pair `U+1F642` แทนตัวอย่างใน trigger information
* ไม่เรียก `StringUtilsTest::testEscapeSurrogatePairs`
* ไม่ใช้ reflection
* ไม่แก้ production code
* ใช้ JUnit 4.12 syntax

---

## 6. LIMITATIONS

มีข้อจำกัดสำคัญอย่างหนึ่ง: source ที่ให้มาไม่ได้แสดง implementation ของ `LookupTranslator` หรือ implementation ของ `StringUtilsTest::testEscapeSurrogatePairs` ดังนั้นจาก source ที่มีอยู่ เราสามารถวิเคราะห์ defect ใน `CharSequenceTranslator.translate()` ได้ แต่ไม่สามารถยืนยันจากข้อมูลที่ให้มาว่า trigger test เดิมใช้ surrogate pair ตัวใด หรือ `LookupTranslator` ใน Defects4J revision นี้คืนค่า `consumed` อย่างไรในทุกกรณี

JIRA ระบุโดยตรงว่า LANG-857 เกิดจาก **bad surrogate-pair handling** และตัวอย่างเดิมทำให้เกิด `StringIndexOutOfBoundsException` ใน `CharSequenceTranslator.translate()` ([Apache Issues][1])

ดังนั้นควรถือผลด้านบนเป็น **source-based expected behavior** จนกว่าจะนำ test class ไปรันจริงกับ:

```text
Lang-6-buggy
Lang-6-fixed
```

และยืนยันว่า **BUGGY fails + FIXED passes** ตามเกณฑ์ของ experiment.
