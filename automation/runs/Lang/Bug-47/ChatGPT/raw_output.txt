## 1. The behavior that differs

The defect is in how `appendFixedWidthPadLeft(Object, int, char)` handles a **null object when `nullText` is also null**.

The method's documented behavior is that a null object uses the builder's null-text value. The default `nullText` is itself `null`. ([Apache Commons][1])

### BUGGY behavior

The buggy implementation effectively does:

```java
String str = (obj == null ? getNullText() : obj.toString());
int strLen = str.length();
```

When:

```java
obj == null
getNullText() == null
```

`str` becomes `null`, and `str.length()` throws a `NullPointerException`.

### FIXED behavior

The fixed implementation handles that situation by treating a null resulting string as an empty string before calculating its length:

```java
if (str == null) {
    str = "";
}
```

The subsequent padding logic therefore creates a field consisting entirely of `padChar`. This behavior is also visible in later Commons implementations of the method. ([Javatips.net][2])

Apache Commons Lang's release notes explicitly identify LANG-412 as **"StrBuilder appendFixedWidth does not handle nulls."** ([Apache Commons][3])

## 2. The likely root cause visible from the source

The root cause is a missing null check after obtaining the string representation of the object.

The buggy flow is:

```text
obj == null
      ↓
getNullText()
      ↓
null
      ↓
str.length()
      ↓
NullPointerException
```

The fixed flow is:

```text
obj == null
      ↓
getNullText()
      ↓
null
      ↓
convert null to empty string
      ↓
str.length() == 0
      ↓
pad the complete requested width
```

This is specifically a null-handling problem rather than a general padding-calculation problem.

The source-level fix also explains why the expected result for a null object with the default null text is a completely padded field: the effective string length becomes zero, so all `width` positions are filled with `padChar`. ([Javatips.net][2])

I would use **6 tests**, divided as follows.

### A. Defect / boundary cases

**Test 1 — null object with a positive width**

**Test 2 — null object appended after existing content**

```text

```

This checks that the fix works when the padding operation starts at a non-zero builder position, rather than merely checking an empty builder.

### B. Representative normal cases

**Test 3 — short non-null value**

```text

expected = "__cat"
```

This exercises ordinary left padding.

**Test 4 — value longer than requested width**

```text
obj = "abcdef"
width = 4
padChar = '_'
expected = "cdef"
```

This exercises the truncation branch:

```java
if (strLen >= width)
```

### C. Regression / boundary controls

**Test 5 — explicitly configured nullText**

```text
nullText = "N/A"
obj = null
width = 5
padChar = '.'
expected = "..N/A"
```

This confirms that the method still uses a configured null-text value rather than always treating null as empty.

**Test 6 — non-positive width**

```text

padChar = '#'
expected = ""
```

The method specifies that zero or negative width has no effect. This also ensures the suite does not accidentally require null handling when the method should not process the value at all. The API documentation states that zero or negative width has no effect. ([Apache Commons][1])

## 5. JUnit 4.12 test code

```java
package org.apache.commons.lang.text;

import static org.junit.Assert.assertEquals;

import org.junit.Test;

public class StrBuilderLang47Test {

    @Test
    public void testAppendFixedWidthPadLeftNullUsesPadding() {
        StrBuilder builder = new StrBuilder();

        builder.appendFixedWidthPadLeft(null, 6, '#');

        assertEquals("######", builder.toString());
    }

    @Test
    public void testAppendFixedWidthPadLeftNullAfterExistingContent() {
        StrBuilder builder = new StrBuilder();
        builder.append("ID:");

        builder.appendFixedWidthPadLeft(null, 4, '0');

        assertEquals("ID:0000", builder.toString());
    }

    @Test
    public void testAppendFixedWidthPadLeftPadsShortValue() {
        StrBuilder builder = new StrBuilder();

        builder.appendFixedWidthPadLeft("cat", 5, '_');

        assertEquals("__cat", builder.toString());
    }

    @Test
    public void testAppendFixedWidthPadLeftTruncatesLongValue() {
        StrBuilder builder = new StrBuilder();

        builder.appendFixedWidthPadLeft("abcdef", 4, '_');

        assertEquals("cdef", builder.toString());
    }

    @Test
    public void testAppendFixedWidthPadLeftUsesConfiguredNullText() {
        StrBuilder builder = new StrBuilder();
        builder.setNullText("N/A");

        builder.appendFixedWidthPadLeft(null, 5, '.');

        assertEquals("..N/A", builder.toString());
    }

    @Test
    public void testAppendFixedWidthPadLeftZeroWidthHasNoEffect() {
        StrBuilder builder = new StrBuilder();

        builder.appendFixedWidthPadLeft(null, 0, '#');

        assertEquals("", builder.toString());
    }
}
```

## 6. Defect Detection Strategy

### Expected behavior

| Test                                                  | BUGGY VERSION                     | FIXED VERSION          | Detects defect? |
| ----------------------------------------------------- | --------------------------------- | ---------------------- | --------------- |
| `testAppendFixedWidthPadLeftNullUsesPadding`          | **FAIL** — `NullPointerException` | **PASS** — `"######"`  | **Yes**         |
| `testAppendFixedWidthPadLeftNullAfterExistingContent` | **FAIL** — `NullPointerException` | **PASS** — `"ID:0000"` | **Yes**         |
| `testAppendFixedWidthPadLeftPadsShortValue`           | PASS — `"__cat"`                  | PASS — `"__cat"`       | No              |
| `testAppendFixedWidthPadLeftTruncatesLongValue`       | PASS — `"cdef"`                   | PASS — `"cdef"`        | No              |
| `testAppendFixedWidthPadLeftUsesConfiguredNullText`   | PASS — `"..N/A"`                  | PASS — `"..N/A"`       | No              |
| `testAppendFixedWidthPadLeftZeroWidthHasNoEffect`     | PASS — `""`                       | PASS — `""`            | No              |

### How detection works

The key assertion is that a null object with the **default null text** should behave like an empty string for fixed-width padding.

For example:

```java
builder.appendFixedWidthPadLeft(null, 6, '#');
assertEquals("######", builder.toString());
```

On the **BUGGY** version:

```text
null
 → getNullText()
 → null
 → str.length()
 → NullPointerException
```

Therefore the test fails.

On the **FIXED** version:

```text
null
 → getNullText()
 → null
 → str = ""
 → str.length() = 0
 → six '#' characters are appended
```

Therefore the test passes.

### Summary

* **Root cause:** `appendFixedWidthPadLeft` calls `length()` on a null string when both the input object and configured `nullText` are null.
* **Targeted behavior:** null input with the default null-text setting must be treated as an empty value and padded to the requested width.
* **Generated tests:** **6**
* **Defect-detecting tests:** **2**
* **Regression/control tests:** **4**
* The tests are independently derived from the source-level null-handling defect and padding branches. They do **not** reproduce the supplied `testLang412Left` trigger or its exact inputs/expected values.
* The issue itself is documented by Apache Commons Lang as LANG-412, concerning `StrBuilder.appendFixedWidth` not handling nulls. ([Apache Commons][3])
