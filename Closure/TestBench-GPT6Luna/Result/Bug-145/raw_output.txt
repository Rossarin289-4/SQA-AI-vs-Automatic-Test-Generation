The public static escaping methods are the test focus: `jsString`, `regexpEscape`, `escapeToDoubleQuotedJsString`, `strEscape`, and `identifierEscape`.
Tests cover quote selection, control and delimiter escaping, HTML-sensitive sequences, charset handling, and supplementary Unicode escaping.

### 2. TEST CASE DESIGN
- `testAsciiStringUsesDoubleQuotes`: `"abc"` → `"abc"`; no quote characters means the default double-quote choice.
- `testSingleQuoteEscapesDoubleQuote`: `a"b` → `"a\"b"`; no single quotes, so double quotes are escaped.
- `testDoubleQuoteSelectionEscapesSingleQuote`: `a'b"c` → `'a\'b"c'`; more single than double quotes selects single delimiters.
- `testBackslashAndControlEscapes`: backslash, newline, tab, carriage return → their explicit escape sequences in a double-quoted string.
- `testNonAsciiStringIsUnicodeEscaped`: `é` → `\u00e9`; null encoder escapes characters above ASCII.
- `testSupplementaryCharacterEscapesAsSurrogatePair`: supplementary character → two four-digit surrogate escapes.
- `testJsStringEscapesScriptTerminatorCaseInsensitively`: `</ScRiPt` → `<\/ScRiPt`; script terminator check is case-insensitive.
- `testJsStringEscapesClosingHtmlComment`: `-->` → `--\>`; `>` following `--` is escaped.
- `testJsStringEscapesClosingCdata`: `]]>` → `]]\>`; `>` following `]]` is escaped.
- `testRegexpEscapeEscapesDelimitersAndBackslash`: `/a\b` → `"\/a\\b"`; regexp mode escapes slash and backslash.
- `testRegexpEscapeDoesNotEscapeGreaterThanWithoutDangerousPrefix`: `a>b` remains unchanged inside quotes; preceding characters do not match either hazardous pair.
- `testExplicitDoubleQuotedEscape`: quote, apostrophe, and backslash use the specified double-quoted escapes.
- `testLatinIdentifierPassesThrough`: Latin identifier text is returned unchanged.
- `testIdentifierEscapesNonAsciiAndPreservesAscii`: `aé` → `a\u00e9`; ASCII is copied and non-Latin character escaped.
- `testIdentifierEscapesControlCharacter`: control character is escaped while following ASCII is copied.
- `testIdentifierEscapesSupplementaryCharacterAsPair`: supplementary character is encoded as its two surrogate escapes.
- `testUsAsciiEncoderEscapesNonAsciiString`: ASCII encoder cannot encode `é`, so it is Unicode-escaped.
- `testLatin1EncoderKeepsRepresentableCharacter`: Latin-1 encoder can encode `é`, so it is emitted directly.
- `testLatin1EncoderEscapesUnrepresentableCharacter`: Latin-1 encoder cannot encode `€`, so it is Unicode-escaped.
- `testEmptyString`: empty input produces only the selected surrounding double quotes.
