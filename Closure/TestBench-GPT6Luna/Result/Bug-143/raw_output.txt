1. SOURCE CODE ANALYSIS

The requested target is unspecified, so selection is exploratory. I selected `RemoveConstantExpressions`, which traverses expression statements, removes expressions without side effects, and extracts side-effecting subexpressions.

2. TEST CASE DESIGN

- `testExpressionStatementWithPureNumberIsRemoved`: numeric literal; pure expression yields no replacement.
- `testExpressionStatementWithPureNameIsRemoved`: name expression; source removes it when it has no side effects.
- `testCallExpressionStatementIsRetained`: direct call; special case retains it.
- `testNewExpressionStatementIsRetained`: direct `NEW`; special case retains it.
- `testAssignmentExpressionStatementIsRetained`: assignment may have side effects and is not a direct call or `NEW`.
- `testCallNestedInAdditionBecomesExpressionStatement`: addition containing a call; extracts the call.
- `testPureExpressionNestedWithCallIsRemoved`: pure operand is excluded while the call remains.
- `testTwoCallsInAdditionProduceTwoStatements`: both calls are gathered into separate expression statements.
- `testExpressionStatementContainingOnlyPureAdditionIsRemoved`: pure arithmetic has no side effects.
- `testNonExpressionStatementIsUnaffected`: `RETURN` is ignored by the callback.
- `testChangeResultIsFalseWhenNoExpressionWasChanged`: direct call remains; no node removal is reported.
- `testChangeResultIsTrueWhenPureExpressionIsRemoved`: removed expression reports a change.
