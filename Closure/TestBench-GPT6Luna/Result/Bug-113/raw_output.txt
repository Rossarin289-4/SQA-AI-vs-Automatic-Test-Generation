### 2. TEST CASE DESIGN

- `testProcessAddsRootNamespaceDeclaration`: provide `alpha` → `var alpha = {}`; root namespace declarations use VAR.
- `testProcessAddsDottedNamespaceDeclaration`: provide `alpha.beta` → dotted assignment expression; dotted names use assignment declarations.
- `testProcessRemovesProvideCall`: provide call → one replacement statement remains.
- `testProcessTracksTopLevelExportName`: `alpha.beta` → exported name `alpha`, the substring before the first dot.
- `testProcessTracksExportNameWithoutDot`: `alpha` → exported name `alpha`, no-dot case adds the whole string.
- `testProcessDoesNotTrackNonStringExportArgument`: name node argument → empty set because only string arguments are recorded.
- `testProcessRemovesAddDependencyCall`: addDependency expression → numeric zero replacement.
- `testProcessRemovesValidRequireWhenChecksOffAndProvided`: provided `alpha` then require → require statement is detached.
- `testProcessLeavesUnrecognizedRequireWhenChecksOff`: unprovided require with checks off → call remains in the expression statement.
- `testProcessRemovesUnrecognizedRequireWhenChecksOn`: unprovided require with warnings enabled → call statement is detached.
- `testProcessAcceptsValidProvideNameWithUnderscore`: `_alpha9` → accepted identifier and VAR declaration.
- `testProcessRejectsProvideNameStartingWithDigit`: `9alpha` → invalid provide remains; no namespace replacement is registered.
- `testHotSwapCallsCompilerProcessing`: empty script → remains SCRIPT after compiler processing.
- `testVisitExportSymbolRecordsNameDirectly`: `x.y` → set contains only `x`, the leading namespace component.
