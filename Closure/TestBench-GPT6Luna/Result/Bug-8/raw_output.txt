        Node combined = root.getFirstChild();

## 1. SOURCE CODE ANALYSIS

The public `process` method is the only usable entry point; `visit` is an override on a private inner class and is not directly constructible here.  
The tests explore adjacent declarations, declaration/assignment merging, assignment exclusions, and unchanged script structures.

## 2. TEST CASE DESIGN

- `testProcessSingleVarLeavesItsDeclaration`: one declaration; it remains the same VAR node with name `a`.
- `testProcessEmptyScriptLeavesItEmpty`: empty script; it has no first child.
- `testAdjacentVarsAreCombined`: two adjacent VAR nodes; source moves both names under one VAR.
- `testVarDeclaratorsKeepTheirInitializerNodes`: two initialized declarations; numeric initializer nodes retain values 1 and 2.
- `testVarThenAssignmentIsConvertedToInitializer`: declaration followed by assignment to its name; assignment RHS 2 becomes the declaration initializer.
- `testVarThenAssignmentAddsDuplicateSuppression`: a merged assignment sets JSDoc information, as the source adds duplicate suppression.
- `testMultipleAssignmentsBecomeNestedInitializer`: two assignments to the declared name are merged; the outer RHS is 5.
- `testAssignmentWithoutPriorVarIsNotCollapsed`: assignment alone has no `hasVar` candidate, so its expression statement remains.
- `testNonNameAssignmentLeftSideIsNotCollapsed`: property LHS fails the name check, preserving the assignment shape.
- `testAdjacentVarsInIfBranchesRemainSeparate`: VAR children of an IF are excluded by the parent-is-IF check.
- `testAStandaloneVarStubDoesNotChangeShape`: the stub blacklists its variable, preventing the following assignment from merging.
- `testVarDeclarationsOnEitherSideOfUnrelatedStatementStaySeparate`: the intervening RETURN ends the consecutive-node scan.
