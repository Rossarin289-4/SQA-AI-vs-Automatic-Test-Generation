        // We'll test the general case of `typeA.isSubtype(typeB)` where `typeA` has an inferred property.
        // Let's assume we have a mechanism to create an object type with inferred properties.

    @Test
    public void testIsSubtype_emptyRecordIsSubtypeOfNonEmptyRecord() throws Exception {
        JSTypeRegistry registry = new JSTypeRegistry(null);
        Map<String, JSType> props1 = Maps.newHashMap();
        RecordType r1 = createRecordType(registry, props1); // {}

        Map<String, JSType> props2 = Maps.newHashMap();
        props2.put("a", registry.getNativeType(JSTypeNative.NUMBER_TYPE));
        RecordType r2 = createRecordType(registry, props2); // {a: number}

        // typeA is r1, typeB is r2.
        // Check properties of typeB (r2): 'a'.
        // r1 does NOT have 'a'. Returns false.
        // This implies that an empty record is NOT a subtype of a non-empty record according to this logic.
        // This contradicts typical structural subtyping where an empty object is a subtype of any object type.
        // Let's re-read the code for `isSubtype` carefully.
        // It checks `RecordType.isSubtype(this, that.toMaybeRecordType());`
        // Inside `RecordType.isSubtype(ObjectType typeA, RecordType typeB)`:
        // `for (String property : typeB.properties.keySet()) { ... }`
        // If typeB is non-empty and typeA is empty, `typeA.hasProperty(property)` will be false, so it returns false.
        // This means the implementation of `isSubtype` considers a record type to be a subtype of another
        // *only if* the subtype has all the properties of the supertype, and satisfies the type constraints.
        // This is more akin to a "supertype" relationship from the perspective of properties.
        // The "record type of the form { a : TYPE_1 } is a supertype of a record type of the form { b : TYPE_2, a : TYPE_1 }"
        // from the Javadoc suggests the opposite.
        // Let's assume the Javadoc interpretation is correct for subtyping.
        // If {a:number, b:string} is a supertype of {a:number}, then {a:number} is a subtype of {a:number, b:string}.
        // The `isSubtype` method seems to implement the check as: `typeA is a subtype of typeB` means `typeB is a supertype of typeA`.

        // Let's re-evaluate based on the Javadoc:
        // "A record type of the form { a : A, b : B } can be assigned to a record of type { a : A }"
        // This implies { a : A } is a subtype of { a : A, b : B }.
        // So, in `isSubtype(this, that.toMaybeRecordType())`, `this` is `typeA` and `that.toMaybeRecordType()` is `typeB`.
        // The current implementation checks if `typeA` has all properties of `typeB` and satisfies type constraints.
        // This means `typeA` is a *supertype* of `typeB` based on standard subtyping definitions.
        // The method name `isSubtype` is confusing here, or the implementation is checking for supertyping.

        // Let's test based on the explicit `isSubtype` implementation:
        // typeA = {} (empty record), typeB = {a: number}
        // For property 'a' in typeB: typeA does not have 'a'. So returns false.
        assertFalse(r1.isSubtype(r2)); // Empty record is NOT a subtype of {a: number} by this implementation.
    }
