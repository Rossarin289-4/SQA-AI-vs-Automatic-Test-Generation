    @Test
    public void testInlineIfAssignmentIsRValue() throws Exception {
        // Test case: `var x = 10; y = x = 5; print(y);`
        // The assignment `x = 5` is used as an R-value.
        // `Candidate.canInline` checks `if (def.isAssign() && !NodeUtil.isExprAssign(def.getParent()))`.
        // This condition means if `def` is an assignment and it's NOT an expression assignment (like `x = 5`),
        // then it cannot be inlined. This condition seems to prevent inlining if the definition itself is an assignment
        // that isn't the top-level expression.
        // Example: `if (x = getValue()) { ... }` - here `x = getValue()` is not an `EXPR_RESULT`.
        // This check seems to be about the definition site itself.

        // Let's consider `var x = (y = 5); print(x);`
        // Here, `def` is `var x = (y=5)`. `def.getLastChild()` is the assignment `y=5`.
        // `def.getParent()` is `VAR`. `NodeUtil.isExprAssign(def.getParent())` is false.
        // So, `def.isAssign()` is false. The condition `def.isAssign()` is false.
        // So the `if (def.isAssign() ...)` block is skipped.

        // This check might be intended for cases like `x = y = 5;` where `y=5` is the assignment that is the R-value.
        // But here `def` would be the assignment `y=5`. `def.getParent()` is the assignment `x = (y=5)`.
        // `NodeUtil.isExprAssign(def.getParent())` would be true for `x = (y=5)`.
        // So `!NodeUtil.isExprAssign(def.getParent())` would be false.
        // Thus, if `def` is `y=5` (as the RHS of `x = (y=5)`), it would be inlinable IF `def.isAssign()` is true.
        // Which is confusing. `NodeUtil.isExprAssign` checks if the parent is `EXPR_RESULT`.

        // A clearer test case: `var x = 10; function f() { return x = 5; }`
        // Here, the definition of `x` is `var x = 10`.
        // The use is in `return x = 5;`.
        // `def` would be `var x = 10`. `def.getParent()` is `VAR`. `NodeUtil.isExprAssign(def.getParent())` is false.
        // The check `if (def.isAssign() && !NodeUtil.isExprAssign(def.getParent()))` is skipped because `def` is not `ASSIGN`.
        // This check seems to apply if the *definition itself* is an assignment.
        // e.g., `x = 10; x = 5; print(x);`
        // The candidate would be for `x = 10`. `def` is `x = 10`. `def.getParent()` is `EXPR_RESULT`.
        // `NodeUtil.isExprAssign(def.getParent())` is true. So `!NodeUtil.isExprAssign(...)` is false.
        // The condition `def.isAssign() && !NodeUtil.isExprAssign(def.getParent())` becomes `true && false`, which is false.
        // So this check doesn't prevent inlining of `x = 10` if its parent is `EXPR_RESULT`.

        // The original comment says: "Check that the assignment isn't used as a R-Value."
        // This implies we should not inline a definition if that definition itself is an assignment, AND that assignment is being used as an R-value elsewhere.
        // This is tricky. The logic `if (def.isAssign() && !NodeUtil.isExprAssign(def.getParent()))`
        // seems to exclude assignments that are not top-level expressions.
        // e.g. `if (x = 5) { ... }`. Here `x = 5` is the definition, its parent is `IF`. `isExprAssign` is false.
        // So this check `def.isAssign() && !NodeUtil.isExprAssign(def.getParent())` would be `true && true`, which is true.
        // Thus, inlining would be prevented. This makes sense.
    }
