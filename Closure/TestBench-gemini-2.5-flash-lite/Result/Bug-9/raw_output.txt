    @Test
    public void testProcessWithRequire() {

        script.setSourceFileName("test.js");

        processor.process(null, root);

        assertEquals("goog.require(\"module$foo\");", root.getChildAtIndex(0).getString());
        // Check require call is rewritten

    }

1. SOURCE CODE ANALYSIS - The `ProcessCommonJSModules` class rewrites CommonJS modules. The `process` method orchestrates the traversal, and the `ProcessCommonJsModulesCallback` handles specific node types like `require` calls, scripts, and `module.exports` assignments. The `toModuleName` static method is also a key part of the transformation. Tests focus on these methods and their transformations.

2. TEST CASE DESIGN -
    - `testToModuleNameBasic`: "foo/bar" -> "module$foo_bar" (basic transformation)
    - `testToModuleNameWithDotSlash`: "./foo/bar" -> "module$foo_bar" (handles leading "./")
    - `testToModuleNameWithDotDotSlash`: "../bar" -> "module$bar" (handles leading "../")
    - `testToModuleNameWithJsExtension`: "foo/bar.js" -> "module$foo_bar" (removes ".js")
    - `testToModuleNameWithDash`: "foo-bar" -> "module$foo_bar" (replaces "-" with "_")
    - `testToModuleNameComplex`: "my-lib/utils/index.js" -> "module$my_lib_utils_index" (combined transformations)
    - `testToModuleNameRelativeBasic`: "bar", "foo" -> "module$bar" (relative addressing)
    - `testToModuleNameRelativeWithDotSlash`: "./bar", "foo" -> "module$bar" (relative addressing with "./")
    - `testToModuleNameRelativeWithDotDotSlash`: "../bar", "foo/baz" -> "module$bar" (relative addressing with "../")
    - `testToModuleNameRelativeComplex`: "my-lib/utils", "my-lib/foo" -> "module$my_lib_utils" (complex relative addressing)
    - `testToModuleNameRelativeSameDir`: "foo", "bar" -> "module$foo" (relative addressing, same directory)
    - `testToModuleNameRelativeParentDir`: "foo", "bar/baz" -> "module$foo" (relative addressing, parent directory)
    - `testNormalizeSourceNameBasic`: "foo/bar" (no prefix) -> "foo/bar"
    - `testNormalizeSourceNameWithPrefix`: "src/foo/bar" (with prefix "src/") -> "foo/bar"
    - `testNormalizeSourceNameWithTrailingSlash`: "src/foo/bar" (prefix "src/") -> "foo/bar" (handles trailing slash in prefix)
    - `testNormalizeSourceNameWithBackslash`: "src\\foo\\bar" -> "foo/bar" (handles backslashes)
    - `testNormalizeSourceNameEmpty`: "" -> "" (empty filename)
    - `testProcessWithRequire`: rewrites `require("foo")` to `module$foo` and adds `goog.require`
    - `testProcessWithModuleExports`: rewrites `module.exports = ...` to `moduleName.module$exports = ...`
    - `testProcessWithGlobalVariableSuffixing`: suffixes global variables with module name (`foo` -> `foo$$module$test`)
    - `testProcessWithExportsInModuleExports`: handles `module.exports` when it's an object literal.
    - `testProcessWithRequireAndModuleExports`: combines `require` and `module.exports` transformation.
    - `testProcessNoDependenciesReported`: checks that dependencies are not reported when `reportDependencies` is false.
    - `testProcessWithMultipleRequires`: ensures multiple `require` calls are handled correctly.
    - `testProcessWithExportsInModuleExportsIf`: checks the `if` condition for `module.exports` override.
    - `testProcessWithModuleExportsAndVariableDeclaration`: checks variable declaration before `module.exports`.
    - `testToModuleNameWithEmptyString`: "" -> "module$" (edge case for `toModuleName`)
    - `testToModuleNameWithOnlyDotSlash`: "./" -> "module$" (edge case for `toModuleName`)
    - `testToModuleNameWithOnlyDotDotSlash`: "../" -> "module$" (edge case for `toModuleName`)
    - `testProcessWithRequireAndDirectModuleExportsAssignment`: checks interaction of require and direct module exports.
