Lang-4 / LANG-882 Test Design Notes

Defect mechanism:
The buggy implementation stores lookup keys as CharSequence objects
directly in a HashMap and performs lookup using CharSequence objects
directly. Different CharSequence implementations may represent the same
text but do not necessarily provide compatible hashCode/equals semantics.

The fixed implementation normalizes both stored lookup keys and lookup
subsequences to String before HashMap insertion and lookup.

Primary test dimensions:
1. CharSequence implementation mismatch
   - String
   - StringBuffer
   - StringBuilder

2. Same textual content across different CharSequence implementations.

3. Lookup success:
   - translated output must match expected value
   - returned consumed length must equal matched key length

4. Lookup failure:
   - unmatched input should return 0
   - output should remain unchanged

5. Greedy matching:
   - overlapping keys
   - shorter and longer keys
   - longest matching key should be selected

6. Index handling:
   - index 0
   - non-zero index
   - input containing prefix/suffix around a match

Defect-oriented priority:
The highest-priority tests should use different CharSequence
implementations for lookup keys and/or input while keeping identical
textual content.

Detection definition:
A generated test detects LANG-882 if:
- it compiles and executes successfully on both versions,
- BUGGY version fails,
- FIXED version passes,
- and the failure is attributable to LookupTranslator lookup
  behavior affected by CharSequence equality/hash semantics.

Original trigger:
The Defects4J developer trigger uses StringBuffer for both the lookup
key and input. Generated tests must not copy the original trigger test
verbatim or reuse its exact test construction as their only defect
detection case.
