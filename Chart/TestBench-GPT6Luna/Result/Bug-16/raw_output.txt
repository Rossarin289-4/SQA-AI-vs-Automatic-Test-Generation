### 2. TEST CASE DESIGN
- `testCountsAndGeneratedKeys`: 2×2 data; counts and key/list agreement follow constructor setup.
- `testExplicitKeysAndIndexes`: explicit keys and absent keys; lookups yield their positions or `-1`.
- `testValueAccessByIndexesAndKeys`: distinct values; start returns start data, end and value return end data.
- `testNullDataCellIsPreserved`: null start cell remains null and end cell is unchanged.
- `testSetStartValueChangesSelectedCell`: set category B; only its start cell changes.
- `testSetEndValueChangesSelectedCell`: set category A; only its end cell changes.
- `testKeyListsContainKeysInOrder`: explicit two-key arrays preserve their order in keys, lists, and indexed access.
- `testSetKeysUpdatesKeyLookups`: replacement keys are returned and indexed at zero.
- `testSetKeysRejectWrongLengths`: arrays with two keys for one row/column throw `IllegalArgumentException`; counts remain one.
- `testInvalidSeriesAndCategoryIndexes`: negative series and category index equal to count throw `IllegalArgumentException`.
- `testUnknownKeysThrowUnknownKeyException`: unknown series/category keys throw the declared exception; valid value lookup returns end data.
- `testNullColumnKeyIsRejected`: null column key throws `IllegalArgumentException`; known key maps to zero.
- `testEqualityComparesDataAndKeys`: identical data compares equal; differing end value and null object compare unequal.
- `testCloneIsEqualAndDataIsIndependent`: clone initially equals original; changing clone data leaves original unchanged and makes them unequal.
- `testGeneratedKeysAndDoubleConstructor`: one-cell double arrays yield the supplied numeric values and one series/category.
- `testEmptyDatasetCounts`: zero-series arrays produce zero counts and empty key lists.
